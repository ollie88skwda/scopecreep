Methodology

How the scoring works.

Last updated 2026-05-24 · Applies to lexicon v1, content script v0.4.0+
No machine learning. No language model. Just a curated lexicon of scope-expansion phrases, lowercased substring matching, and a small severity-weighted score. You can read the entire algorithm here. The lexicon is open data.

The 30-second version

  1. Extension scans each Slack message you receive against 225 hand-curated phrases grouped into 15 categories.
  2. Each matched phrase contributes a small score: severity × category_weight.
  3. If a message's total score is ≥ 2, it gets a badge.
  4. Badge color: amber for medium-severity flag, brick red if any high-severity phrase was matched.
  5. Messages you wrote yourself are skipped (matched against the display name you configure).

The scoring formula

For every message, the extension runs this loop:

score = 0
hits = []
for entry in lexicon.phrases:
    if entry.phrase in message.lower():
        s = severity_weight[entry.severity]   // low=1, medium=2, high=3
        w = category_weight[entry.category]   // 0.6 .. 1.2
        score += s * w
        hits.append(entry)

if score >= 2:
    flag(message, hits)

That's it. Whole algorithm.

Worked example

Client message: "Looks great! Can you also add a hover state? While you're at it, fix the spacing too — shouldn't take long."

Phrase matchedSeverityScore

while you're at it (additive)high3 × 1.0 = 3.0
shouldn't take long (favor framing)high3 × 0.9 = 2.7

Total: 7.7. Well above the 2.0 threshold. Badge: brick red (high-severity hits present).

Why a threshold of 2

A single low-severity match (e.g. just ASAP → 1 × 0.6 = 0.6) does not trigger a badge. This avoids alert fatigue on innocuous messages. The threshold of 2 means:

  • One medium-severity phrase = 2.0 → flags (just barely)
  • One high-severity phrase = 3.0 → flags clearly
  • Two low-severity phrases together = 2.0 → flags
  • One low alone = under threshold, no badge

What we explicitly don't do

  • No machine learning. The "score" is a sum of integers. No model. No training data. No GPUs.
  • No LLM call at runtime. The extension doesn't talk to OpenAI, Anthropic, Google, or any AI provider when scanning messages.
  • No fuzzy matching. The phrase "can you also" matches that exact 3-word sequence (case-insensitive). It does NOT match "if you can also" via similarity scoring or anything tricky. This makes the algorithm fully predictable.
  • No telemetry. We do not see what the extension flagged on your machine. We could not see it even if we wanted to — see the privacy policy.
  • No "smart" context detection. If a client quotes a previous message that contains "can you also" and the quote happens to be in their reply, the extension will flag it. False positive. Dismiss it; we use dismiss/flagged ratios to refine the lexicon over time.

How the lexicon evolves

Maintained as src/data/lexicon.json in the open-source repo. Process:

  1. Users flag false positives via the popup "Dismiss" button.
  2. Dismiss/flag ratio per phrase is tracked privately on each user's device (Pro tier opt-in aggregated reporting forthcoming).
  3. When a phrase exceeds 30% dismiss rate across opted-in users, it's reviewed and either rephrased, severity-lowered, or removed.
  4. New phrases come from public freelance forums (r/freelance, freelance Twitter rants, indie hacker threads) — curated, never automated.
  5. Lexicon version bumps documented in CHANGELOG.md.

Skipping your own messages

To avoid flagging your own messages, the extension compares each message's sender to a display name you set in Settings. Case-insensitive, trimmed. If your Slack display name is "Ollie Nguyen" and a message header reads "Ollie Nguyen", that message is skipped (and tagged in the DOM with data-scopecreep-self="1" so you can verify). If unset, all messages are processed (legacy fallback for first-run users).

Try it yourself

The popup's Settings view has a Test mode textarea. Paste any sample message; you'll see exactly which phrases matched, the computed score, and whether the message would be flagged. Runs locally — nothing is sent anywhere.

Open data

The complete lexicon is in the src/data/lexicon.json file in the open-source repo. Read it, audit it, send pull requests for missing phrases or bad ones. The categorization, severity tags, and category weights are all visible.
